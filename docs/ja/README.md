# Octopus Energy Japan 連携（Home Assistant）

Octopus Energy Japan（OEJP）の電気使用量を Home Assistant に取り込む、非公式の
読み取り専用カスタム統合です。

> [!WARNING]
> 本プロジェクトは Octopus Energy Japan および Kraken Technologies とは
> 一切関係がなく、公式な提供・推奨・サポートを受けていません。

> [!IMPORTANT]
> **まだ接続できません。** OEJP から OAuth クライアント ID が発行されておらず、
> 利用者が自分で作成する手段もないため、サインインの相手が存在しません。
> それ以外の機能は完成しており、検証も済んでいます。
> 進捗は [`OAUTH_APPLICATION_STATUS.md`](../OAUTH_APPLICATION_STATUS.md)（英語）に
> 記録しています。

規範となる詳細仕様は英語版 [`USER_GUIDE.md`](../USER_GUIDE.md) です。本ページは
日本語利用者向けの案内です。

## できること

30分単位の使用量、日・週・月の集計、訂正に強い Energy Dashboard 統計、そして
アカウント・契約・請求の要約を取得します。

**読み取り専用** です。OEJP 側の設定を変更したり、検針値を送信したり、支払いを
行うことは一切ありません。パスワードを受け取ることもありません。サインインは
ブラウザ上の OEJP 公式ページで行われます。

## 対応範囲

| 対応 | 内容 |
|---|---|
| 電気の供給地点 | ログインで見えるすべてのアカウントの、すべての供給地点 |
| 複数アカウント | 1つのログインに紐づく全アカウントを1つの連携で扱います |
| 買電・売電 | 売電は OEJP が提供している場合のみ表示されます |
| メーター・機器・レジスタ | OEJP が公開している場合に検出します（必須ではありません） |
| 終了済みアカウント・供給地点 | 検出しますが既定では無効。設定で選択できます |
| ガス | **非対応** です |

## 主な用途

- OEJP のアプリを開かずに、昨日や今月の使用量を確認する
- Energy Dashboard で、太陽光・蓄電池・回路計測と並べて表示する
- 「今日の使用量がしきい値を超えたら通知」などの自動化を作る
- 長期の履歴を残す。OEJP が提供するのは概ね直近30日ぶんですが、連携が取得済みの
  データは保持されるため、履歴はその先も伸びていきます

**料金計算の道具ではありません。** [制限事項](#制限事項)を参照してください。

## 導入手順

クライアント ID が発行されたあとの手順です。

1. HACS にこのリポジトリを追加し、**Octopus Energy Japan** をインストール
2. Home Assistant を再起動
3. **設定 → デバイスとサービス → アプリケーション認証情報** で、OEJP から
   発行されたパブリック クライアント ID を登録（シークレット欄は空のまま）
4. **設定 → デバイスとサービス → 統合を追加 → Octopus Energy Japan**
5. ブラウザで OEJP にサインインし、アクセスを許可

アプリケーション認証情報を登録する前に統合を追加しようとすると、Home Assistant が
「先に認証情報を追加してください」という案内を表示して停止します。登録できる
クライアント ID がまだ存在しないため、現時点ではこれが正常な動作です。

**My Home Assistant を有効にしておいてください。** `default_config:` に含まれる
ため、通常の環境ではすでに有効です。サインインは `my.home-assistant.io` を経由して
戻る仕組みで、OEJP に登録されているリダイレクト先はこの 1 つだけです。構成を
絞っている場合は `configuration.yaml` に `my:` を追加してください。無効のままの
ときは、OEJP 側でリダイレクト先が拒否される前に、連携が理由を説明して停止します。

### 入力する項目

セットアップ中に入力するものはありません。API キー、契約番号、供給地点特定番号は
不要で、サインインしたアカウントからすべて自動検出します。

有効なアカウントと供給地点は常に有効で、無効化できません。新しい供給地点は
自動的に追加されます。終了済みのものだけ、**設定** から個別に選べます。

## 提供するエンティティ

エンティティ名には契約番号・供給地点特定番号・住所を一切含めません。

### 供給地点ごと（買電・売電それぞれ）

既定で有効: 最新報告区間の使用量、今日・昨日・今週・今月・先月の使用量、
最新データ日時、データ遅延、供給地点の状態、データ利用可能。

期間の集計値は、その期間が完全に埋まるまで **不明** を返します。同期途中の
中途半端な数値を「少ない日」として見せないためです。

**「現在の電力」に相当するエンティティはありません。** OEJP が公開するのは30分間の
合計値であり、区間平均を瞬時値として見せることは誤りだからです。

### アカウントごと

既定で有効: アカウント状態、現在の料金プラン、現在の契約開始日時・終了日時。

既定で無効（金銭情報のため）: アカウント残高、延滞残高、最新請求額、
最新請求書発行日、最新請求の支払期日、最新取引額。必要なものだけエンティティ設定
から有効にしてください。

## 更新の仕組み

| 対象 | 間隔 |
|---|---|
| 使用量 | 30分ごと（直近72時間を再取得） |
| アカウント・供給地点の検出 | 24時間ごと |
| 契約・請求 | 12時間ごと |
| 全体の再照合 | 1日1回（今月と前月） |

**使用量は遅れて届きます。** OEJP は30分値を数時間後、ときにはそれ以上あとに
公開します。これは事業者側の計量データ処理によるもので、連携の不具合ではありません。
データが欠けているのではなく、まだ公開されていない状態です。

**使用量は訂正されます。** 請求期間が締まると、OEJP は区間を別のバージョンで
再発行し、値が変わることがあります。連携は累計値ではなく各区間そのものを保存して
いるため、訂正が届くと該当区間とそれ以降の統計を決定的に再計算します。

## Energy Dashboard

**設定 → ダッシュボード → エネルギー → 電力の使用量** で、供給地点の
**統計** を選んでください。期間エンティティ（今日・今月など）ではなく統計を
使います。期間エンティティは表示用で、訂正に対応した正式なデータは統計側です。

詳細は [Energy Dashboard の統計](ENERGY_DASHBOARD.md) を参照してください。

## 制限事項

**電気料金は表示しません。** OEJP は区間ごとに `costEstimate` を返しますが、
意図的に公開していません。実際の請求書と照合したところ、実際の料金プランを
再現しない簡略モデルでした。料金プランには段階が2つあるのに1つしか使わず、
日単位の基本料金は区間値では表現できません。これを「あなたの料金」として
表示すると、請求書のどの項目とも一致しない数字に事業者の権威を与えることに
なります。根拠は [契約・料金プラン・請求情報](CONTRACT_AND_BILLING.md) に
記録しています。

**料金プランの単価も表示しません。** OEJP は単価を型のない事業者独自の
データ構造で返し、どれがお客さまの供給地点に適用されるかを確実に判定できません。

**「使用量 × 単価」の概算も提供しません。** 日本の電気料金は、段階制の
電力量料金、日割りの基本料金、月ごとの燃料費調整、再エネ賦課金、消費税の
組み合わせです。単一の単価では再現できません。

**OEJP の履歴は概ね30日ぶんです。** 導入直後は約1か月から始まり、そこから
ローカルに蓄積されます。

**集計期間は請求期間と一致しません。** 請求期間は深夜すぎの検針時刻まで、
連携の「今月」は日本時間の暦月です。設計上、この2つは一致しません。

**契約情報が取得できない場合があります。** アカウントによっては契約情報の
参照が許可されていません。使用量には影響せず、該当エンティティが利用不可に
なり、修復メッセージで説明します。

## 困ったときは

まず **設定 → システム → 修復** を確認してください。連携が検知できる状況ごとに
平易な説明を表示し、操作が必要かどうかも書いてあります。多くの場合、操作は不要です。

| 症状 | 考えられる原因 |
|---|---|
| My Home Assistant が必要と表示される | `my` が無効。`my:` を追加するか `default_config:` を戻して再起動 |
| 集計値が「不明」 | その期間がまだ完全に埋まっていない（導入直後は正常） |
| 最新区間が数時間前 | OEJP の通常の公開遅延。「データ遅延」を確認してください |
| エンティティが一斉に利用不可 | 更新が失敗した状態。自動的に再試行します |
| 再接続を求められた | OAuth の認可が期限切れ、または取り消された |
| 金銭関連のエンティティが無い | 既定で無効。個別に有効化してください |
| Energy Dashboard の過去の値が変わった | OEJP が区間を訂正した（正常な動作） |

不具合を報告する際は、[診断情報](DIAGNOSTICS.md) の手順に従ってください。
診断ファイルに個人情報は含まれないため、中身を確認せずに添付できます。
ログの貼り付けは避けてください。事業者からのメッセージが含まれることがあります。

## 削除する場合

**設定 → デバイスとサービス → Octopus Energy Japan → 削除** です。OEJP へ認可の
取り消しを依頼し、保存済みの使用量・同期状態・ローカル秘密鍵を削除します。

意図的に残るものが2つあります。

- **Energy Dashboard の統計**: 連携を削除しただけでエネルギー履歴が失われないよう
  Home Assistant の recorder に残ります。不要なら **開発者ツール → 統計** から
  削除してください。
- **アプリケーション認証情報**: 再追加時にクライアント ID を入れ直さずに済むよう
  残ります。不要なら **設定 → デバイスとサービス → アプリケーション認証情報** から
  削除してください。

## プライバシー

データはお客さまの Home Assistant の中に留まります。外部への telemetry 送信や、
開発者が運用するサーバーへの送信は行いません。詳細は
[`PRIVACY.md`](../../PRIVACY.md)（英語）を参照してください。
