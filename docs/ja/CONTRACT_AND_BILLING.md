# 契約・料金プラン・請求情報

状態: OAuth Application 発行前のプレアルファ版

この連携は、Octopus Energy Japan のアカウント状態、契約、料金プラン名、
請求・取引の要約を Home Assistant のエンティティとして提供します。正式な
インストール方法は、OEJP から Public OAuth Application が発行され、実
アカウント検証が完了した後に公開します。

規範となる英語版の仕様は
[`docs/CONTRACT_AND_BILLING.md`](../CONTRACT_AND_BILLING.md) です。

## 提供するエンティティ

既定で有効:

- アカウント状態
- 現在の料金プラン
- 現在の契約開始日時
- 現在の契約終了日時

既定で無効（利用者が明示的に有効化します）:

- アカウント残高
- 延滞残高
- 最新請求額
- 最新請求書発行日
- 最新請求の支払期日
- 最新取引額

残高や請求に関するエンティティは個人の金銭情報であるため、既定では作成
されません。Home Assistant のエンティティ設定から必要なものだけを有効に
できます。

## 権限が一部だけ許可されている場合

アカウント情報、契約情報、請求情報はそれぞれ別の API 操作として取得します。
そのため、いずれか一つの権限がない場合でも、他の情報は引き続き表示されます。
取得できなかった情報に対応するエンティティのみが「利用不可」になります。

電力使用量、ledger、Energy Dashboard の統計は、これらの操作の結果に影響
されません。契約・請求情報が取得できなくても使用量の記録は継続します。

認証そのものが失敗した場合は、Home Assistant が再認証を要求します。

## 更新間隔

契約・請求情報は12時間ごとに更新します。使用量の30分ごとの更新とは別の
仕組みで動作します。

連携の起動時には、まず使用量エンティティの準備を完了させ、その後に契約・
請求情報の取得を開始します。契約・請求情報の取得が起動を遅らせることは
ありません。

そのため、表示される値は最大で12時間前の状態です。契約や請求の性質上、
これは意図した設計です。

取得に失敗した場合、古い値をそのまま表示し続けることはありません。対象の
エンティティが「利用不可」になります。

## 金額の単位について

金額は OEJP が返す値をそのまま `JPY` として表示し、換算は行いません。これは
OEJP が円単位で金額を返すという前提に基づいています。この前提は、まだ
OEJP からの回答または実アカウント検証で確認できていません。確認は公開
リリース前に行います。

## 公式料金と単価を表示しない理由

OEJP が返す公式コスト（`costEstimate`）と料金プランの単価は、内部モデルとして
取得・保持していますが、エンティティや統計としては公開していません。

理由は次の4点が未確認であることです。

- 公式コストを取得するために必要な OAuth 権限
- 金額の通貨と単位
- すべての区間に公式コストが付与されるかどうか
- reading が訂正されたときに公式コストも訂正されるかどうか

単価についてはさらに、OEJP が送配電事業者・エリア・区分ごとに複数の単価を
返すため、利用者の供給地点にどの単価が適用されるかを確実に判定できません。
推測した単価で金額を表示すると、誤った値を正しい値のように見せることに
なります。

利用者が入力した単価による料金推定も、1.0 の範囲では提供しません。

## プライバシー

Account number、SPIN、住所、氏名、メールアドレス、OAuth token は、エンティティ
の状態、属性、名称、ログ、診断情報へそのまま表示しません。請求書や取引の
明細全体をエンティティの属性に保存することもありません。外部 telemetry は
送信しません。
